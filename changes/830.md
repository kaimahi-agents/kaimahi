### Added

- `kmx cluster up --step cluster --offline-bundle DIR` creates or reuses a kind cluster from a locally cached, independently pinned node image without provisioning tools or running model/Orka setup. The node-only `kmx-offline/v1` profile verifies local OCI metadata, binary identity and actual engine image/platform/rootfs before mutation. Existing online behavior is unchanged.

### Upgrading

- Offline mode now requires an existing local filesystem Unix socket before probes. Docker uses its selected CLI context; Podman requires exactly one explicit `CONTAINER_HOST` or `CONTAINER_CONNECTION` socket selection, not implicit native selection. TCP/SSH and ambiguous endpoints refuse without starting a service; online behavior is unchanged.
- Offline reuse requires the selected kubeconfig server, effective CA and TLS/proxy settings to match read-only configuration from the verified node. Different credentials are allowed; relative CA-file paths without a resolved source origin refuse. Mismatched/broken entries are never overwritten, and an existing context cannot be overwritten by creating an absent cluster. Stopped nodes that cannot supply expected configuration refuse before start. Genuinely missing contexts still export on reuse. Offline children disable kubectl preferences to prevent command defaults overriding the verified connection; preference files and online commands are unchanged.
- New cluster creation requires existing `/bin/sh` and an executable temporary directory. Offline kind calls use the selected engine, not provider auto-detection.
- This profile does not install Orka or import archives. Node creation and exact reuse were walked on Linux amd64 with classic Docker 29.9.2, kind 0.33.0, kubectl 1.35.1 and node v1.35.0. Blocked-egress creation, Podman, Docker's containerd image store and native arm64 execution remain unverified; metadata pins are not runtime qualification. The guest owns cache import and lifetime.
